## 2024-05-18 - React State Driven by Video Timeupdate Anti-Pattern
**Learning:** Using React state (e.g. `setCurrentTime(t)`) driven by the `<video>` element's `timeupdate` event causes excessive component re-renders (up to 4 to 66 times per second depending on browser). In `WhatsAppStatusPreview`, this led to constantly re-rendering the whole component (mock UI, phone frame, video overlay) simply to update a visual progress bar and a time text snippet.
**Action:** Always avoid updating React state directly on `timeupdate` for purely visual or frequent updates. Instead, track time internally as needed, but rely on React Refs (`useRef`) to bypass React's render cycle and manually modify the underlying DOM nodes (`progressRef.current.style.width`, `timeTextRef.current.textContent`).
